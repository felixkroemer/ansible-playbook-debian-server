# Avahi mDNS Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ensure avahi is installed, running, and publishing the server's hostname over `.local` mDNS.

**Architecture:** Add a new `tasks/avahi.yml` task file following the existing `tasks/authorized-keys-sync.yml` import pattern. It installs `avahi-daemon` and `avahi-utils`, enables/starts the service, and verifies at runtime that `<hostname>.local` resolves to an IPv4 address. Import it from `main.yml`.

**Tech Stack:** Ansible (apt, systemd, command, assert modules), avahi-daemon, avahi-utils.

## Global Constraints

- Target host: Debian (use `apt`).
- Advertise the system's existing hostname via `ansible_hostname` — no custom name config.
- No firewall changes.
- No avahi-daemon.conf changes.
- Verification must confirm actual mDNS publishing, not just service running.
- Use short-form module names (`apt`, `systemd`, `command`, `assert`) consistent with existing task files.

### Task 1: Add avahi tasks file

**Files:**
- Create: `tasks/avahi.yml`

**Interfaces:**
- Consumes: `ansible_hostname` (host fact).
- Produces: file `tasks/avahi.yml` that installs packages, enables/starts the service, and verifies resolution. Consumed by `main.yml` via `import_tasks`.

- [ ] **Step 1: Create `tasks/avahi.yml`**

```yaml
- name: Install avahi-daemon and avahi-utils
  apt:
    name:
      - avahi-daemon
      - avahi-utils
    state: present
- name: Enable and start avahi-daemon service
  systemd:
    name: avahi-daemon
    enabled: yes
    state: started
- name: Verify server resolves via .local address
  command: avahi-resolve-host-name {{ ansible_hostname }}.local
  register: avahi_resolve
  until: avahi_resolve.stdout | regex_search('\\d+\\.\\d+\\.\\d+\\.\\d+')
  retries: 10
  delay: 3
```
